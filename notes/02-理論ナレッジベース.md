# 理論ナレッジベース設計メモ (2026-10-16)

## 目的
既存の音楽理論を素早く検索して曲に採用でき、自作の理論も同じ形式で作り上げられる場にする。
理論は和声・リズム・旋律・形式・編成など多面的で、理論が理論を含むメタ構造も持つ。

## エントリの3層
| 層 | 内容 |
|---|---|
| 記述 | 定義、背景、出典、ライセンス |
| 形式 | 音程集合・規則・制約として機械可読にしたもの |
| 操作 | 解析 / 検査 / 生成のコード |

## 構造
- **側面(facet)**: 和声 / 旋律 / リズム / 編成・楽器 / 音色 / 形式・構成 / 調律。1エントリが複数の側面に属せる
- **スコープ(粒度)**: 音 → 音程 → 和音 → フレーズ → 節 → 楽章 → 曲 → 編成。コメントの粒度と対応させる
- **辺(関係)**: `is-a` / `part-of` / `constrains` / `conflicts` / `alternative` / `derived-from`
- **検査**: 曲のスコープ階層と理論グラフを突き合わせ、成立範囲、制約違反、上位理論からの影響を返す

## 採用と記録
理論を曲の範囲に適用すると、理論ID・版・出典がその範囲のコメント/意図に記録される。

## MCP ツール案
`search_theory` / `apply_theory` / `check_theory` / `define_theory`

## 段階
1. L1: 和音とスケール
2. L2: リズムと旋律
3. L3: 節・形式(メタ構造)
4. L4: 編成・音色

## 出典とライセンス
再利用できるものに限る(Open Music Theory (CC)、Wikipedia/Wikidata、music21 など)。取り込み時にソースごとの条件を記録する。
市販書籍は書誌情報とページ参照のみ。

## 2026-10-20 追記
- 保存形式: 1エントリ = 1つの Markdown。本文が「記述」、frontmatter が「形式」、「操作」はコードへの参照。関係は `[[リンク]]`(種類は frontmatter)。Obsidian 互換の vault にし、グラフビューで見られるようにする
- 慣習も理論に含める。`kind`(定義 / 規則 / 慣習 / 個人の観察)と `context`(ジャンル、時代、文化)を持たせる
- 3層は全部そろわなくてよい。形式にしにくい理論は記述だけで始める
- `license` と `visibility` の欄を先に設け、公開範囲の調整は最終段階で行う
- 全体の決定事項と未決の論点は `00-全体設計と論点.md` に集約した
